## 2. Background Summary

Modern enterprises generate massive volumes of logs from network devices, servers, OS, applications, databases, cloud services, containers, endpoint security tools, IAM systems, IoT devices, and other hardware/software platforms — in Syslog, JSON, XML, CSV, CEF, LEEF, proprietary vendor formats, and application-specific schemas.

Consequences (per verbatim PS):

- Diversity of structures breaks centralized monitoring, SecOps, compliance reporting, incident investigation, and threat analytics.
- Security teams burn effort writing source-specific parsers / normalization rules before SIEM, data lake, or ML platforms can use the data.
- Hybrid, multi-cloud, AI-driven adoption makes a universal, extensible log standard for current + future sources increasingly critical.

---

## 3. Detailed Description — Verbatim Essence

> Design and develop a Universal Log Pre-processing Framework (framework) capable of ingesting, parsing, normalizing, and standardizing logs and events generated by **any hardware or software system**.

Framework must:

- Support diverse event sources **while preserving the original event data** for forensic and compliance purposes.
- Transform heterogeneous logs into a **unified schema** enabling consistent analytics, correlation, visualization, threat hunting, anomaly detection, and ML applications.
- Be **scalable, extensible, vendor-agnostic**, and suitable for **Big Data environments handling billions of events per day**.

PRISM interpretation (from `README.md` / `HANDOFF_SESSION.md` / `FRS_NFRS.md`): 4-plane Rust + Python architecture (Ingestion / Data / Control-AI / Integrity + Presentation), OCSF v1.9.0 Class 4001 output, BLAKE3 + Merkle Parquet vault, DLQ + Drain3/OpenJev/Ollama auto-parser loop, 50,000+ EPS/core, <50 MB RSS, air-gapped.

## 4. Expected Solutions a–k Checklist (verbatim)

From `docs/PS_SIH26156_VERBATIM.md` — "This solution should cover universal event schema and processing framework that enables:"

- [ ] **a)** Preserve complete raw event data without information loss.

- [ ] **c)** Normalize fields into a common event taxonomy.
- [ ] **d)** Maintain traceability between normalized and original events.

- [ ] **h)** AI/ML-ready security and operational analytics.
- [ ] **i)** Reduced parser development effort.

## 5. Current Scope (frozen — perimeter devices only)

Verbatim from `docs/PS_SIH26156_VERBATIM.md`:

> Build a framework that converts **any perimeter network device-generated log or event — regardless of source, format, vendor, or technology** — into a standardized, lossless, analytics-ready representation for next-generation SIEM and cybersecurity platforms.

Implication for datasets: prioritize **perimeter** sources (firewalls, IDS/IPS, VPN concentrators, proxy/WAF, routers/switches, Zeek/Suricata/Snort) over generic host/app logs. Enterprise-wide sources (servers, DBs, cloud, containers, IAM, IoT) remain in scope for solution item (f) visibility testing but are secondary to perimeter ground truth.

Output contract (from `docs/architecture/DATA_DICTIONARY_AND_IPC.md`): **OCSF v1.9.0 Class 4001 Network Activity** (`category_uid=4`, `class_uid=4001`) + PRISM extensions `metadata.history_hash` (BLAKE3) and `metadata.vault_uri` (Parquet block). IPC: Rust→Python via `/var/run/prism/dlq.log` JSONL (`utf8:`/`b64:`-prefixed `raw_payload`), Python→Rust via `/etc/prism/rules/*.vrl + *.yaml` hot-reload.
