# TUI Architecture Design Document: Spectre Prism (`crates/prism-tui`)

## 1. Overview
This document outlines the architectural design for a multi-pane asynchronous Terminal User Interface (TUI) in Rust, built with Ratatui. The application will monitor internal messaging systems and provide real-time visibility into EPS (Events Per Second) metrics, DLQ (Dead Letter Queue) rates, and a live Merkle ticker.

## 2. Core Architecture

The architecture relies on four foundational crates:
*   **Ratatui**: For rendering UI components.
*   **Crossterm**: For the terminal backend and capturing terminal events (via the `event-stream` feature).
*   **Tokio**: For managing asynchronous tasks, network I/O, and concurrent background polling.
*   **Tokio MPSC Channels**: For message-passing between background tasks and the main UI thread.

### 2.1 The Event-Action Loop
The core of the application will use a **Centralized Event Loop** pattern to prevent blocking the UI thread. The system is decoupled into two message flows:

1.  **Events:** Raw inputs (Key presses, Mouse clicks, Window resizes, or Tick/Render intervals) generated by terminal and time-based streams.
2.  **Actions:** High-level application intents (e.g., `Action::EpsUpdated(u32)`, `Action::Quit`).

```rust
pub enum Event {
    Tick,
    Render,
    Key(crossterm::event::KeyEvent),
    Resize(u16, u16),
}

pub enum Action {
    Quit,
    Resume,
    Suspend,
    UpdateEps(f64),
    UpdateDlq(f64),
    AppendMerkle(String),
}
```

### 2.2 Concurrency Model (`tokio::select!`)
A dedicated background Tokio task will read Crossterm events and forward them via an unbounded `mpsc` channel. 

The main application loop will await messages using `tokio::select!` or standard channel `recv()`, updating state and initiating a render *only* when necessary (Targeted Rendering) or at a steady frame rate (Immediate Mode).

## 3. State Management & Component Pattern

To support a scalable multi-pane architecture, we will implement the **Component Trait Pattern**. Each visual pane of the dashboard operates as a self-contained unit of logic and presentation.

### 3.1 The `Component` Trait
Every UI pane implements a shared trait, standardizing initialization, event handling, and rendering:

```rust
pub trait Component {
    /// Initialize async tasks or subscriptions
    fn init(&mut self, action_tx: UnboundedSender<Action>) -> Result<()> { Ok(()) }
    
    /// Handle user input (optional)
    fn handle_events(&mut self, event: Option<Event>) -> Result<Option<Action>> { Ok(None) }
    
    /// Mutate state based on incoming system actions
    fn update(&mut self, action: Action) -> Result<Option<Action>> { Ok(None) }
    
    /// Render the component onto the designated area
    fn draw(&mut self, frame: &mut Frame, area: Rect) -> Result<()>;
}
```

### 3.2 State Synchronization
*   Each Component holds its own specific subset of state (e.g., `EpsMetricsPane` holds historical EPS arrays; `MerkleTickerPane` holds a string buffer).
*   The Main App instance orchestrates the components. When the App receives an `Action` from a background worker, it iterates through all registered components and calls `component.update(action)`.

## 4. UI Layout & Multi-Pane Dashboard

The layout will divide the terminal window into distinct sections using `ratatui::layout::Layout` and `Constraint`.

### 4.1 Dashboard Wireframe
```text
┌────────────────────────────────────────────────────────┐
│  Spectre Prism Header (App Title & Status)             │
├──────────────────────────┬─────────────────────────────┤
│                          │                             │
│       EPS Metrics        │         DLQ Rate            │
│   (Line Chart / Gauge)   │   (Bar Chart / Gauge)       │
│                          │                             │
├──────────────────────────┴─────────────────────────────┤
│                                                        │
│                  Merkle Ticker                         │
│           (Scrolling List / Text Log)                  │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 4.2 Layout Implementation
Inside the application's global `draw` method, the frame area will be split before delegating chunks to child components:

```rust
let vertical_chunks = Layout::default()
    .direction(Direction::Vertical)
    .constraints([
        Constraint::Length(3),      // Header
        Constraint::Percentage(50), // Middle Panes (EPS / DLQ)
        Constraint::Percentage(50), // Bottom Pane (Merkle)
    ])
    .split(frame.area());

let middle_chunks = Layout::default()
    .direction(Direction::Horizontal)
    .constraints([
        Constraint::Percentage(50), // EPS
        Constraint::Percentage(50), // DLQ
    ])
    .split(vertical_chunks[1]);

// Pass areas to components
self.header.draw(frame, vertical_chunks[0])?;
self.eps_pane.draw(frame, middle_chunks[0])?;
self.dlq_pane.draw(frame, middle_chunks[1])?;
self.merkle_pane.draw(frame, vertical_chunks[2])?;
```

### 4.3 Component Specifics
1.  **EPS Metrics Pane:** Utilizes `ratatui::widgets::Chart` or `Sparkline` to visualize recent throughput. State maintains a circular buffer of EPS measurements.
2.  **DLQ Rate Pane:** Utilizes `ratatui::widgets::Gauge` or `BarChart` to visualize errors. Highlighted with red/yellow styles depending on threshold values.
3.  **Merkle Ticker Pane:** Utilizes `ratatui::widgets::List` or `Paragraph` with a block outline. Appends new Merkle tree node hashes as they are received, automatically scrolling to the latest entry.

## 5. Summary & Directory Structure

Target implementation directory: `crates/prism-tui/src/`
*   `main.rs`: Entry point, sets up the terminal and the main `App` instance.
*   `app.rs`: Implements the `App` struct, the main event loop, and layout orchestration.
*   `events.rs`: Crossterm event stream handler (publishes `Event`).
*   `action.rs`: Defines the `Action` enum for inter-task communication.
*   `components/`: Sub-module for UI components.
    *   `mod.rs`: Defines the `Component` trait.
    *   `eps.rs`: EPS line chart implementation.
    *   `dlq.rs`: DLQ gauge/bar implementation.
    *   `merkle.rs`: Scrolling list implementation for the ticker.
